# Daily Reflections - Project Report

## Executive Summary

Daily Reflections is a comprehensive Android journal application developed using the MVVM architecture pattern. The app enables users to create, manage, and review personal journal entries with mood tracking and tagging capabilities. This report documents the complete development process, design decisions, and implementation details.

## 1. Project Overview

### 1.1 Application Purpose

Daily Reflections serves as a digital journaling platform that helps users:
- Document daily experiences and thoughts
- Track emotional patterns through mood selection
- Organize entries with custom tags
- Maintain a searchable archive of memories
- Reflect on personal growth over time

### 1.2 Key Features Implemented

✅ Create, read, update, and delete journal entries  
✅ Browse all entries with preview and date  
✅ Detailed view of individual entries  
✅ Mood tracking (10 different moods)  
✅ Tag-based entry organization  
✅ Search functionality  
✅ Material Design 3 compliant UI  
✅ MVVM architecture with Room database  
✅ Comprehensive unit tests  
✅ Lifecycle-aware components

System Design\n\n### 3.1 Architecture Pattern: MVVM\n\n**Benefits chosen:**\n- Clear separation of concerns\n- Easy to test business logic\n- Lifecycle-aware with LiveData\n- Supports configuration changes\n\n### 3.2 Database Schema\n\n```sql\nCREATE TABLE journal_entries (\n    id INTEGER PRIMARY KEY AUTOINCREMENT,\n    title TEXT NOT NULL,\n    content TEXT NOT NULL,\n    createdAt INTEGER NOT NULL,\n    updatedAt INTEGER NOT NULL,\n    mood TEXT,\n    tags TEXT,\n    imagePath TEXT\n);\n```\n\n### 3.3 Technology Stack\n\n| Component | Technology | Version |\n|-----------|-----------|----------|\n| Language | Java | 11 |\n| UI Framework | Android Material | 1.9.0 |\n| Database | Room | 2.5.2 |\n| ViewModel | AndroidX Lifecycle | 2.6.1 |\n| Min SDK | Android | 21 (Lollipop) |\n| Target SDK | Android | 34 (Android 14) |\n\n## 4. Implementation Details\n\n### 4.1 Core Components\n\n#### Data Model: JournalEntry\n\nThe JournalEntry class represents a single journal entry with the following attributes:\n\n- **id**: Auto-generated primary key\n- **title**: Entry title (String)\n- **content**: Main entry content (String)\n- **createdAt**: Creation timestamp in milliseconds (long)\n- **updatedAt**: Last update timestamp in milliseconds (long)\n- **tags**: Comma-separated tags (String)\n- **mood**: Emoji and mood text (String)\n- **imagePath**: Optional image path (String)\n\n#### Data Access Object (DAO)\n\nThe EntryDao interface provides type-safe database access with methods for:\n- Insert, update, delete operations\n- Query all entries (sorted by date)\n- Query single entry by ID\n- Search entries by title or content\n- Filter by mood\n\n#### Repository Pattern\n\nThe EntryRepository acts as a single source of truth for data operations:\n- Abstracts database details from ViewModel\n- Handles background threading\n- Manages data consistency\n- Provides LiveData observables\n\n#### ViewModel Layer\n\nThe EntryViewModel:\n- Holds LiveData for all entries\n- Manages lifecycle-aware data\n- Coordinates between UI and Repository\n- Survives configuration changes\n\n### 4.2 User Interface\n\n#### MainActivity - Entry List Screen\n\n- **RecyclerView** displays all entries in a scrollable list\n- **EntriesAdapter** handles efficient list rendering with DiffUtil\n- **FloatingActionButton** for adding new entries\n- **Empty state** message when no entries exist\n- **LiveData observation** automatically updates list\n\n#### AddEditEntryActivity - Create/Edit Screen\n\n- **Title input** for entry name\n- **Content area** for detailed text (200dp height)\n- **Tags field** for comma-separated categorization\n- **Mood spinner** with 10 emotional states\n- **Input validation** before saving\n- **Auto-detect** edit vs. create mode\n\n#### EntryDetailActivity - View Details Screen\n\n- **Full content display** with proper formatting\n- **Date display** (creation and update times)\n- **Mood indicator** showing selected emotion\n- **Tags display** for quick reference\n- **Edit button** to modify entry\n- **Delete button** with confirmation dialog\n\n### 4.3 Material Design Implementation\n\n**Color Scheme:**\n- Primary: #6200EE (Purple)\n- Primary Dark: #3700B3\n- Secondary: #03DAC6 (Cyan)\n- Error: #B3261E (Red)\n\n**Components Used:**\n- MaterialCardView for entry cards\n- AppBarLayout with Toolbar\n- FloatingActionButton for primary actions\n- MaterialTextInputLayout for form fields\n- Material Buttons and Dialogs\n- Material Color System\n\n## 5. Lessons Learned\n\n### 8.1 Technical Lessons\n\n1. **MVVM Architecture Benefits**\n   - Lifecycle handling is transparent\n   - Testing becomes significantly easier\n   - Configuration changes don't cause data loss\n\n2. **Room Database Efficiency**\n   - LiveData integration is seamless\n   - Query optimization is built-in\n   - Type safety prevents SQL errors\n\n3. **Material Design Implementation**\n   - Components are well-designed\n   - Consistency across platform\n   - User expectations are met\n\n4. **Threading Management**\n   - Repository pattern handles threading cleanly\n   - No blocking operations on UI thread\n   - No memory leaks with LiveData\n\n### 8.2 Design Lessons\n\n5. **Separation of Concerns**\n   - Each layer has single responsibility\n   - Easy to modify one layer without affecting others\n   - Testing is straightforward\n\n6. **Abstraction with Repository**\n   - Easy to swap database implementation\n   - Can add caching layer later\n   - Cloud sync becomes easier\n\n### 8.3 Development Process Lessons\n\n7. **View Binding**\n   - Eliminates findViewById() boilerplate\n   - Null-safe view access\n   - Type-safe at compile time\n\n8. **LiveData Lifecycle**\n   - Automatically handles UI updates\n   - No manual subscription management\n   - Configuration changes handled automatically\n\n9. **Testing First**\n   - Tests caught model issues early\n   - Test-driven design improves code\n   - Regression testing prevents bugs\n\n10. **Code Documentation**\n    - JavaDoc helps understand code quickly\n    - Clear comments prevent misunderstandings\n    - Future maintainers appreciate documentation\n\n## 9.
